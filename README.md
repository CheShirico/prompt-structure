# Анализ промптов: как контекст меняет ответ

Сравнение двух версий одного запроса к ИИ («до» — без контекста, «после» — с конкретными вводными).
Цель — показать, что именно в структуре промпта влияет на качество ответа.

Разобрано два примера:

1. [Акции и мероприятия для пивного бара](#пример-1-акции-и-мероприятия-для-пивного-бара)
2. [Отчёт о прибылях и убытках для бара](#пример-2-отчёт-о-прибылях-и-убытках-для-бара)

Общие выводы — в [конце документа](#общие-выводы-по-двум-примерам).

---

# Пример 1. Акции и мероприятия для пивного бара

## 1. Промпты

### Промпт «до»

> Напиши 3 варианта акции и мероприятии для пивного бара

### Промпт «после»

> Напиши 3 варианта возможных акции и мероприятии для пивного бара в г. Алматы, при условии что бар работает с четверга по воскресенье с 15.00 до 00.00, для привлечения новых гостей в четверг и воскресенье, с расчетом на аудиторию от 25 до 35 лет, без выделения большого бюджета на проведение этих мероприятии

---

## 2. Структура промптов

| Элемент промпта | «До» | «После» |
|---|---|---|
| **Задача** (что сделать) | ✅ 3 варианта акций и мероприятий | ✅ то же |
| **Объект** | ✅ пивной бар (без деталей) | ✅ пивной бар |
| **Локация** | ❌ не указана | ✅ г. Алматы |
| **График работы** | ❌ не указан | ✅ чт–вс, 15:00–00:00 |
| **Цель** | ❌ не указана | ✅ привлечь новых гостей в чт и вс |
| **Целевая аудитория** | ❌ не указана | ✅ 25–35 лет |
| **Ограничения (бюджет)** | ❌ не указаны | ✅ без большого бюджета |
| **Количество вариантов** | ✅ 3 | ✅ 3 |

**Итог:** в первом промпте задана только задача и количество. Во втором добавлены пять недостающих элементов: локация, график, цель, аудитория, ограничение по бюджету.

---

## 3. Что изменилось в ответах

### 3.1. Краткое содержание ответов

**Ответ «до»** — универсальные идеи для любого бара:
1. «Пивной паспорт» — программа лояльности со штампами за новые сорта.
2. «Тап-тейковер» — вечер одной пивоварни раз в две недели по четвергам.
3. «Пивной квиз + Happy Hour» — по вторникам.

**Ответ «после»** — идеи под конкретные условия:
1. «Квиз-четверг» с ранним Happy Hour (17:00–19:00, для тех, кто идёт с работы).
2. «Sunday Chill» — настолки, спортивные трансляции, фиксированный воскресный сет.
3. «Колесо удачи» + «Приведи друга» — механика на оба дня с контентом от гостей.

### 3.2. Сравнение по параметрам

| Параметр | Ответ «до» | Ответ «после» |
|---|---|---|
| **Привязка ко дням** | Вторник и «четверг раз в 2 недели», то есть дни, когда бар может быть закрыт | Только четверг и воскресенье, с распределением по дням |
| **Цель акций** | Удержание гостей (лояльность), имидж, загрузка будней | Привлечение **новых** гостей |
| **Время суток** | Не учитывалось | Happy Hour 17–19 под выход с работы, квиз в 20:00, воскресенье — спокойный формат |
| **Локальный контекст** | Нет | Тенге (₸), 2GIS, чаты коворкингов и бизнес-центров Алматы, Telegram |
| **Аудитория 25–35** | Нет привязки | После работы, компании, настолки, футбол/UFC/F1, UGC в сторис |
| **Бюджет** | «Низкий/средний», встречается идея со средним бюджетом (закупка партии, приезд пивовара) | Только низкий, очень низкий и минимальный; идея со средним бюджетом убрана |
| **Конкретика расходов** | Только слова «низкий/средний» | Оценки в ₸ (игры, колесо, розыгрыш) — это оценки, не проверенные данные |
| **Юридический аспект** | Нет | Предупреждение об ограничениях рекламы алкоголя в Казахстане |
| **Измерение результата** | Нет | Рекомендация сравнить через 4–6 недель: число гостей, средний чек, новые гости |
| **Итоговая рекомендация** | Таблица «цель → вариант» | Таблица «день → бюджет → эффект» и план запуска: №1 по четвергам, №2 по воскресеньям, №3 поверх |
| **Следующий шаг** | Предложение уточнить формат бара | Предложение подготовить анонсы, контент-план, вопросы для квиза |

### 3.3. Что сохранилось

- Формат: три пронумерованных варианта с блоками «суть», «зачем», «бюджет».
- Идея квиза пережила переработку: из вторника её перенесли на четверг.
- Обе версии заканчиваются сводной таблицей и предложением продолжить.

### 3.4. Что исчезло и почему

| Убрано | Причина |
|---|---|
| «Пивной паспорт» (лояльность) | Цель сменилась: нужны новые гости, а не удержание существующих |
| «Тап-тейковер» | Требует среднего бюджета (партия, пивовар) |
| Вторник | Бар по вторникам не работает |

---

## 4. Выводы

1. **Чем больше вводных, тем меньше «воды».** Универсальный ответ подходит всем и потому почти никому. Вторая версия сразу применима к конкретному бару.
2. **Цель важнее темы.** «Привлечь новых» и «удержать своих» дают принципиально разные механики. Без цели ИИ выбирает случайно.
3. **Ограничения сужают поиск.** Бюджет и график отсекли часть идей и заставили придумать дешёвые механики вроде UGC и «приведи друга».
4. **Локация подтягивает локальные детали**: валюту, площадки продвижения, правовые нюансы.
5. **Аудитория определяет тон и формат**: после работы, компании, соцсети.

---

## 5. Шаблон хорошего промпта

```
Задача:       Напиши [N] вариантов [чего именно]
Объект:       для [тип бизнеса / продукта]
Локация:      в [город / регион]
Условия:      [график, сезон, площадка]
Цель:         для [привлечения / удержания / роста чека]
Аудитория:    [возраст, интересы, поведение]
Ограничения:  [бюджет, сроки, ресурсы, запреты]
Формат ответа: [таблица / список / с примерами цен]
```

Опционально: добавить критерий успеха («как поймём, что сработало») и попросить сравнение вариантов в таблице.

---

## 6. Ограничения этого анализа

- Сравнивались ответы одной модели на два промпта, по одному ответу на каждый. При повторном запуске ответы будут отличаться.
- Цифры в ₸ в ответе «после» — ориентировочные оценки, а не проверенные цены рынка Алматы.
- Замечание об ограничениях рекламы алкоголя в Казахстане носит общий характер и требует проверки у юриста.

# Пример 2. Отчёт о прибылях и убытках для бара

## 1. Промпты

### Промпт «до»

> создай простую таблицу-Отчет о прибылях и убытках для бара

### Промпт «после»

> Сформируй шаблон простой в понимании таблицы-Отчете о ежедневных прибылях и убытках для бара с кухней на 1 месяц, с учетом того что данные должны вноситься ежедневно по окончанию дня и выложи здесь

---

## 2. Структура промптов

| Элемент промпта | «До» | «После» |
|---|---|---|
| **Задача** | ✅ создать таблицу | ✅ сформировать **шаблон** таблицы |
| **Объект** | ✅ бар | ✅ бар **с кухней** |
| **Периодичность отчёта** | ❌ не указана | ✅ ежедневный |
| **Горизонт** | ❌ не указан | ✅ 1 месяц |
| **Как используется** | ❌ не указано | ✅ данные вносятся ежедневно по окончании дня |
| **Критерий качества** | ⚠️ «простую» (без пояснения) | ⚠️ «простой в понимании» (без измеримых признаков) |
| **Куда выдать результат** | ❌ не указано | ✅ «выложи здесь» |

**Итог:** в первом промпте не заданы период, детализация и сценарий использования, поэтому их пришлось выбирать самому. Во втором добавлены четыре элемента: периодичность, горизонт, сценарий ввода данных и место выдачи результата. Требование «простоты» осталось субъективным в обеих версиях.

---

## 3. Что изменилось в ответах

### 3.1. Краткое содержание ответов

**Ответ «до»** — годовой отчёт по месяцам. Один лист «ОПУ»: 12 столбцов с января по декабрь и «Итого за год». Строки: выручка (4 статьи), себестоимость, валовая прибыль и маржа, операционные расходы (6 статей), операционная прибыль, налог, чистая прибыль. Ставка налога вынесена в отдельную жёлтую ячейку. Примерные данные внесены за январь–март.

**Ответ «после»** — рабочий инструмент для ежедневного ввода. Два листа:
- «Дни» — одна строка на каждый день месяца. Вводятся только синие ячейки: выручка (бар, кухня, прочее) и расходы дня (закупки бара и кухни, зарплата смены, прочие). Дата, день недели, итоги, прибыль дня, нарастающий итог и маржа считаются сами.
- «Итоги» — настройки (месяц, аренда, коммунальные, прочие постоянные расходы), результат месяца и инструкция из шести пунктов.

### 3.2. Сравнение по параметрам

| Параметр | Ответ «до» | Ответ «после» |
|---|---|---|
| **Единица учёта** | Месяц (12 столбцов) | День (30–31 строка) |
| **Организация листов** | Один лист, всё вместе | Два листа: «Дни» для ввода, «Итоги» для настроек и результата |
| **Ввод данных** | Вносить можно в любую синюю ячейку, порядок не определён | Только в строку текущей даты, сценарий «каждый вечер» описан в инструкции |
| **Даты** | Названия месяцев текстом | Даты и дни недели подставляются формулами от одного первого дня месяца |
| **Кухня и бар** | Выручка разделена по видам напитков и еды, расходы общие | Выручка и закупки разделены на бар и кухню в каждой строке дня |
| **Постоянные расходы** | Аренда и коммунальные вводятся по месяцам вместе с остальными | Вынесены на лист «Итоги» и вычитаются один раз за месяц, а не в каждой строке дня |
| **Налог** | Есть, ставка 10% как допущение | Не включён, чтобы не усложнять |
| **Защита от ошибок ввода** | Нет | Проверка ввода: только числа от 0; лишние дни месяца серые |
| **Нарастающий итог** | Нет | Есть по дням |
| **Контрольные показатели** | Маржа валовая и чистая | Плюс число рабочих дней, средняя выручка за рабочий день, лучший день |
| **Пример данных** | Три месяца | Одна строка-пример (по правилу для шаблонов) |
| **Подача результата** | Только файл. Предпросмотр в чате пришлось запрашивать отдельным сообщением | Предпросмотр листов сразу в чате вместе с описанием |

### 3.3. Что сохранилось

- Формат результата: файл Excel с формулами, а не значения, вписанные вручную.
- Валюта (тенге), шрифт, цветовая схема «синий — ввод, чёрный — формулы».
- Пометка, что данные примерные, и оговорка, что формулы не пересчитывались в Excel или LibreOffice.
- Принцип упрощения: без налогов и лишних статей.

### 3.4. Что исчезло и почему

| Убрано | Причина |
|---|---|
| 12 столбцов по месяцам | Горизонт сменился с года на один месяц |
| Налог с прибыли | Для ежедневного ввода это шум, налог считается не по дням |
| Три месяца примерных данных | Для шаблона достаточно одной строки-примера |
| Деление выручки на разливное, бутылочное, кухню | Заменено разделением на бар и кухню, понятным при вводе вечером |

---

## 4. Выводы

1. **Сценарий использования меняет архитектуру.** Фраза «данные вносятся ежедневно по окончании дня» превратила годовую сводку в таблицу ввода: строки по датам, проверка чисел, нарастающий итог, отдельный лист для настроек.
2. **Периодичность и горизонт нельзя оставлять на усмотрение исполнителя.** В первой версии период (год) и детализация (месяц) были выбраны наугад, и они не подошли.
3. **Слово «шаблон» задаёт требования.** Шаблон должен быть чистым, с инструкцией и примером, а не готовым отчётом с данными.
4. **«Выложи здесь» избавляет от лишнего шага.** Когда место выдачи указано в промпте, результат появляется в чате сразу, без дополнительного запроса.
5. **«Простой» не работает без критерия.** Слово «простой» присутствует в обеих версиях, но без измеримых признаков оно трактуется по-разному. Полезно уточнять, например: «не больше двух листов, ввод только в выделенные ячейки, без налогов».

## 5. Шаблон промпта для таблицы или отчёта

```
Задача:        Сформируй шаблон [какого документа]
Объект:        для [тип бизнеса / подразделения]
Период:        на [1 месяц / квартал / год]
Детализация:   по [дням / неделям / месяцам]
Сценарий:      данные вносит [кто], [когда], [откуда берёт]
Состав:        какие статьи учитывать и какие исключить
Простота:      [число листов, ввод только в выделенные ячейки, инструкция]
Формат выдачи: [файл Excel / Google Sheets / показать здесь]
```

---

## 6. Ограничения этого анализа

- Сравнивались ответы одной модели, по одному ответу на каждый промпт. При повторном запуске они будут отличаться.
- Формулы в таблицах проверены отдельным Python-движком, а не в самом Excel или LibreOffice. Все суммы в тенге в примерах условные.
- Файлы таблиц в репозиторий не добавлены, в README описано только их содержимое.

# Общие выводы по двум примерам

Каждое добавление к промпту меняло ответ в одном из двух направлений:

| Тип контекста | Примеры из разборов | Как меняется ответ |
|---|---|---|
| **Предметный** (кто, где, для кого, зачем) | Город, график работы, аудитория, цель, бюджет, тип заведения («бар с кухней») | Ответ становится применимым к конкретной ситуации, идеи отсеиваются по ограничениям |
| **Процессный** (как и когда будет использоваться результат, в каком виде нужен) | Ежедневный ввод вечером, период 1 месяц, «шаблон», «выложи здесь» | Меняется структура и формат результата: что вводит человек, что считается само, как показан ответ |

Чем меньше промпт оставляет на угадывание, тем меньше правок нужно после первого ответа. Универсальная схема: задача, объект, цель, условия, ограничения, сценарий использования, формат выдачи.
